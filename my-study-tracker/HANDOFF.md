## 今回の質問への回答と公開手順

「受け取ったファイルをGitHubへ上げれば、すでにホームにあるアイコンから新版を使えるか」には、同じGitHub Pagesの公開元・URLへ全ファイルを上書きし、公開処理が成功していれば可能と案内した。

- ZIP自体のアップロードでは更新されない。解凍したフォルダーの中身を、既存の `index.html` がある場所へ上書きする。余分な階層を増やさない。
- 既存の公開ブランチ／フォルダー／リポジトリ名・公開URLを維持する。公開完了には最大10分程度かかることがある。
- 同じ端末・同じ配信元の通常更新ではlocalStorageを保持。別URL・別端末への移行やサイトデータの削除とは別の話である。
- オンラインでホームアイコンから開く。新版取得後に自動再読み込み。v67以後は開いたままのアプリに戻る場合も確認する。旧版から最初に更新するときは一度アプリを閉じて開き直すと確実。
- 申請予定の入力途中やバックアップ復元中は再読み込みを保留し、保存／入力クリア後に適用する。
- 実際の公開URL・GitHub設定は提供されていない。ユーザーのGitHubには変更を加えておらず、公開完了を確認したとは案内しない。
- 参考：GitHub公式「Configuring a publishing source」「Creating a GitHub Pages site」。URLはREADME.mdに記載。

## 保存とバックアップ

| localStorageキー | 内容 |
| --- | --- |
| cp-enrollments | `{学期ID: [科目コード,...]}`。従来形式を維持。 |
| cp-progress | `{科目コード: 完了章数}`。従来どおり全学期共通。 |
| cp-current-sem | 選択中の学期ID。 |
| cp-migrated-v1 | 旧コマ数を章数へ変換済みのマーカー。 |
| cp-records-v1（新規） | `{学期ID: {科目コード: {grade, assignments, examTaken}}}`。gradeは空文字またはA/B/C/D/F/K/P、assignmentsは提出済み回数番号の配列、examTakenは真偽値。 |
| cp-applications-v1（新規） | `{id,semesterId,title,date,allDay,time,notes,done,revision}`の配列。日付YYYY-MM-DD、時刻HH:mm（日本時間）。終日のtimeは空文字。最大1000件。 |
| cp-save-journal-v1（新規・一時） | 複数キー保存前の旧値。書込失敗はロールバックし、中断は次の起動で回復。コミット後に削除。 |

- 動画進捗の学期別移行はしていない。再履修でも動画は前学期と共有されると画面に明記。既存の視聴記録を課題提出済み・受験済みに変換しない。
- 学期・科目別の記録は履修選択を解除しても保持。成績画面には記録の残る科目も表示する。課題を再編集するには当該学期で再選択する。
- saveStateは保存失敗時に最後に保存できた状態をメモリーにも復元する。フォームは保存失敗時に入力を残す。
- バックアップは `format: "my-study-tracker-backup"`, `version: 2`, `exportedAt`, `data: {enrollments,progress,currentSemesterId,records,applications}`。最大5 MiB。
- version 1復元時は追加2項目を空にし、確認ダイアログでも明示。取消・不正データで現在の記録を変更しない。旧アプリはversion 2を拒否する。
- サーバー保存・ログイン・端末間自動同期はない。

## 計算・日程の境界

- GPAはA=4/B=3/C=2/D=1/F=0を単位数で加重。Fは分母に含め、K/P/未登録は除外。分母0は未計算。全学期の参考GPAは登録された全履修回を含む。再履修時の大学独自の除外規則は未確認なので公式GPAとは呼ばない。
- 修得単位はA〜DとPを科目コードで重複除外。Pだけの科目は区分未確認として別記し、MC卒業要件への割当からは除外。単位修得・卒業の公式認定はしない。
- 動画＋課題の記録数から3分の2の目安を表示する。Cloud Campusの受験資格を認定する表示はしない。
- ICSは元の出席テーブルに時刻がある締切のみ採用。開講方式未確認・概算は除外。期末は対象キーとタイムゾーン付き時刻のあるもののみ。春の旧日付のみの期末行は対象外、秋の8区分は対応。
- ICSの時刻は日本時間からUTCへ変換。終日はVALUE=DATE、DTENDは排他的な翌日。特殊文字のエスケープ・UTF-8の75オクテット折返し・CRLFに対応。
- UIDは日程を編集しても変えない。ただしファイル再取込時の重複抑止はカレンダー製品による。継続同期・削除同期・通知設定は行わない。
- SWは同一版のシェルを使用し、新しい版を一括取得して切り替える。削除するキャッシュはmy-study-tracker-で始まるものだけ。アプリの更新でlocalStorageを消さない。
