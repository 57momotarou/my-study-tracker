# Study Tracker 開発ルール

このファイルはサイバー大学の学習管理用PWA「Study Tracker」専用です。`index.html` と同じプロジェクトルートに置き、このディレクトリ以下の作業に適用します。

## 作業の始め方

- 本書 → `HANDOFF.md` → 今回必要なソース・テストの順に読む。毎回、会話履歴や全ファイルを読み直す必要はない。
- 最新のユーザー指示を優先する。実装の有無は現在のコードで確認し、過去の「追加します」という発言を実装完了と扱わない。
- 日本語で簡潔に説明する。ユーザー自身がコードを書き換える前提にせず、完成したファイルを渡す。
- 承認済みの作業は繰り返し確認せず進める。機能の依頼・提案・実装済み・検証済みを区別する。
- 既存の動作と保存データを保ち、依頼と関係しない全面改修やフレームワークへの移行を避ける。
- 他のアプリの仕様を持ち込まない。本プロジェクトは店舗管理・家計管理アプリとは別物。

## 構成と実行

- HTML / CSS / 通常のJavaScriptによる静的PWA。ビルド処理、`package.json`、サーバー側の保存処理はない。
- `index.html` のスクリプトはグローバルを共有する。依存順序を維持し、`app.js` を最後に読み込む。
- `data.js` が科目・学期・バッジのマスター、`curriculum.js` が開講条件・卒業計画・バッジ計画と2026秋日程、`attendance.js` が授業日程の計算。
- `app.js` が状態・保存・起動・ナビゲーション。画面は `render-*.js`、学生ガイドは `student-guide.js`、移行は `data-transfer.js`。
- v67から、`study-records.js` が成績・課題・期末、`calendar-export.js` が申請予定とICS、`pwa-update.js` が更新確認を担当する。
- ローカル確認はプロジェクトルートで `python3 -m http.server 8000` を実行し、`http://localhost:8000/` を開く。PWA機能の確認には対応するブラウザーと安全な配信元が必要。

## 保存と互換性

- 既存のlocalStorageキー `cp-enrollments` / `cp-progress` / `cp-current-sem` / `cp-migrated-v1` を維持する。アプリ更新やアイコン更新で初期化しない。
- 履修は学期IDごとの科目コード配列。現在の進捗は科目コードごとの累積章数で、学期ごとの独立記録ではない。
- 旧形式のコマ数から章数への変換は一度だけ行う。`cp-migrated-v1` を保持し、再起動や復元で繰り返し4倍にしない。
- 科目コード・学期IDを保存識別子として扱う。名称の修正でコードを変更しない。廃止・非開講の科目も既存記録のために残す。
- v67の追加保存キー `cp-records-v1`（学期別の成績・提出・受験）と `cp-applications-v1`（申請予定）、保存失敗回復用の `cp-save-journal-v1` を保つ。詳細はHANDOFF.md参照。
- 新しい永続項目は、初期値・読み込み・正規化・保存・バックアップ出力・復元・失敗時の回復を一緒に更新する。
- 既存のversion 1バックアップを読み込めるようにする。現在の出力はversion 2。追加データを落とす旧版へ新形式を誤って復元できないよう、形式バージョンを管理する。
- 復元は形式を検証してから内容と上書き確認を示す。キャンセル・不正ファイル・保存失敗で現在のデータを壊さない。
- 同じ配信元での更新と、別URL・別端末への移行を区別する。後者はバックアップ／復元で対応し、クラウド同期があると案内しない。

## 守る表示・計算ルール

| 対象 | ルール |
| --- | --- |
| デザイン | ネイビーを主役にする。現在の本・チェック・回路のアイコンと、控えめな黄色アクセントを維持する。 |
| 対象端末 | PCとiPhoneを考慮する。固定ヘッダー・学期タブ・下部ナビ・セーフエリアの重なりや横スクロールを増やさない。 |
| 設定 | 「履修設定」「学生ガイド」「データ」の導線とガイド検索を維持する。 |
| 計画と実績 | 履修選択、動画視聴、課題提出、期末受験、成績・単位修得を混同しない。選択だけで取得済みや卒業確定と表示しない。 |
| 出席 | 既存の章進捗から課題提出・期末受験を自動的に完了扱いにしない。未開講の操作制限はタッチ・マウス・キーボードで共通にする。 |
| GPA | 資料にあるA=4・B=3・C=2・D=1・F=0を使用。Fは分母に含め、K・Pと成績未登録は除外する。対象0単位の表示も定義する。 |
| 卒業計画 | 現在のMC基準は専門62・教養24・外国語12・共通26の計124単位。外国語選択4単位の教養代替、共通へ回す外国語8単位上限、必修条件を保ち、二重計上しない。 |
| バッジ | 科目の選択と正式取得を区別する。プラチナ等の手動確認条件を、科目選択だけで達成にしない。 |
| 日程 | 確定資料の日本時間と例外日を優先する。締切日の残日数と締切時刻超過を分ける。概算を正式日程として表示・出力しない。 |

## 資料の扱い

- 提供された17枚の整理結果は `REVIEW.md`、アプリ内の要約は `student-guide.js` にある。資料の日付と未確認事項を引き継ぐ。
- 新規開講・廃止の「予定」を確定事項へ変えない。科目の単位や開講方式を、資料なしに推測して変更しない。
- MCとCP、編入・認定単位等の個別条件を混ぜない。公式の成績・卒業・バッジ認定を代行する表示にしない。
- 新しい規則や日程へ更新する場合は提供資料または大学の一次資料で確認する。写真の手書きチェックから本人の成績を推測しない。

## 変更時の検証

- JavaScriptを変更したら `node --check 対象ファイル.js`、関連ロジックを変更したら `TZ=Asia/Tokyo node tests/regression.cjs` を実行する。
- 保存・成績・締切などの変更は、境界時刻、旧データ、取消・失敗、科目の重複や再履修など、実際に壊れ得る条件を検証する。
- 新規JSを足すときは `index.html` の読み込み順と `sw.js` の `APP_SHELL` を更新する。配信リソースを変更したらキャッシュ版を進める。
- 更新確認を変更する場合は、ホーム画面への復帰・オフライン・入力中の再読み込み保留・旧キャッシュからの切替を確認する。APP_VERSIONとSWのキャッシュ版をそろえる。
- サービスワーカーのキャッシュ削除は `my-study-tracker-` の範囲に限定する。他アプリのキャッシュを消さない。
- 文書だけの変更では、不要なアプリコード変更やキャッシュ更新をしない。
- 自動チェック成功を実ブラウザー・iPhone実機での動作確認と言い換えない。未検証の範囲を明記する。

## 完了と引き継ぎ

- `HANDOFF.md` に完了事項・残件・最新成果物・実際に行った検証を更新する。`REVIEW.md` の「未実装」なども実装の進行に合わせて直す。
- 配布ZIPは `my-study-tracker/` 配下に必要ファイルと本書・引き継ぎ書を含める。不要な一時ファイル、個人の学習バックアップ、元写真は同梱しない。
- ZIP整合性と必要ファイルの収録を確認し、現在の作業ファイルと配布物の一致を確認する。
- ユーザーは以前ZIPの表示・ダウンロードで困っている。ファイル名は短くし、文書を依頼された場合は単独ファイルも渡す。
- ファイルは利用環境の保存手順で永続保存し、実在する成果物へのリンクを返す。未保存・未検証のものを完了扱いにしない。
